## Dev log

### API-6389 — OAuth connection records
*Repo:* `master_service` · *Branch:* `API-6389-m2-storage` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `392684680` `248ebb1bd`
- OAuth connection and refresh-token rows now store the company and user by integer id like the rest of the schema; tokens keep UUIDs because they are read outside the region, where integer ids collide.
- Connections record when the app last refreshed and why and by whom they were revoked (user, admin, app disconnect, or detected token reuse), so support and admins can explain a dropped connection.
- The client id column now fits full metadata-document URLs, so storage never limits which apps can connect.
- Each connection now has its own UUID for Zuper APIs, following the codebase's uid convention; the OAuth library's internal grant id is kept separately and never exposed.

### API-6389 — OAuth reuse alerts and hardening
*Repo:* `master_service` · *Branch:* `API-6389-m3.6-hardening` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `96af2ad4f` `f0c5c6e0c`

- Login and consent pages can no longer be embedded in another site's frame or cached, closing a clickjacking path on the Allow button.

### API-6389 — OAuth tokens on API routes
*Repo:* `master_service` · *Branch:* `API-6389-m4-token-verification` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `841cb6fdb`
- OAuth access tokens now work on regular API routes: they are verified locally (signature, region, issuer, audience, revocation) and give the request the same user shape as an API key, so role and custom-field rules apply unchanged.
- Each route declares the scope it needs; routes without one refuse OAuth tokens, so nothing becomes reachable by accident. Jobs and customers read routes are open for now, pending the MCP team's route list.
- Session logins, API keys and the other key types take exactly their old path; a new test drives the real auth middleware with OAuth on and off to prove it. Scope names now follow module keys (job:read, customer:read).

### API-6389 — Revoking OAuth access tokens
*Repo:* `master_service` · *Branch:* `API-6389-m5-revoke` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `6d60b6d29`
- Apps can now revoke an OAuth access token, not just a refresh token; the token stops working on its next API call instead of staying valid for up to an hour.
- Revoking a refresh token still ends the whole connection, including its live access tokens; invalid tokens and other apps' tokens are ignored with a normal success response, as the OAuth spec requires.

### API-6389 — Company-created OAuth apps
*Repo:* `master_service` · *Branch:* `API-6389-m5b-company-apps` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `ef9a15c05` `726ff885e`
- Company admins can now create OAuth apps for their own integrations (n8n, private Zapier) in Settings, and update, rotate the secret of, or delete them; the secret is encrypted at rest and shown only once.
- Only users of the company that owns an app can connect through it; this is checked before the password and again at consent, so a recent login session cannot be used to connect another company's app.
- Deleting an app revokes all its connections in the company at once, and rotating a secret cuts off the old one immediately while existing connections keep working.
- The OAuth apps list now pages like every other Zuper list (page, count, sort; total records and pages in the response).

### API-6389 — Daily OAuth cleanup schedule
*Repo:* `master_service` · *Branch:* `API-6389-review-fixes` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `baff8e237`
- Expired OAuth refresh tokens and connections are now cleaned up once a day at 2 AM US Eastern instead of every hour; expired rows can't be used anyway, and a daily run clears a day's volume in a few batches.
