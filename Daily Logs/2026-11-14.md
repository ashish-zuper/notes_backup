## Dev log

### API-6845 — Custom object review changes: record numbering
*Repo:* `master_service` · *Branch:* `api-6845-06-review-changes` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `2abe62a5d`

- New custom objects number their records without zero-padding by default (PRM-1 instead of PRM-0001); objects that already chose a padding keep it.
- Admins can set the number records start from, when creating an object or later; it can only move forward, so a record number is never given out twice.
- The starting number is kept only on the object's record counter, the same counter the company counter settings edit, and object details show the number the next record will get.

### API-6845 — Custom object review changes: fields, permissions, notes and lists
*Repo:* `master_service` · *Branch:* `api-6845-06-review-changes` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `def52caea`

- A new custom object's primary field now sits in the default field group, as fields created without a group do in other modules; no "General" group is created.
- The custom object permissions API now lists only the access roles that have rights saved for the object (the apps take the full role list from the access role API), and drops the is_default flag.
- A note can now be on records of several custom objects at once (one record per object), like a note can be on a Job and a Customer together; each record is access-checked and gets its own activity entry and event.
- Custom object record list, filter and details APIs accept fields_to_select, with the same syntax other modules use.
