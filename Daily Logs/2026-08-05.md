## Dev log

### API-5305 — Product updates unblocked for SRS-imported products

*Repo:* `master_service` · *Branch:* `API-5305` · *Ticket:* [API-5305 — Product PUT API failing for products imported from SRS Template](https://linear.app/zuperinc/issue/API-5305/product-put-api-failing-for-products-imported-from-srs-template) · *Commits:* `6b458c1b0`

- Editing any product imported from an SRS order template failed with "Invalid Image / Attachment", which blocked every field on the form, not just the image. The url validation added across the modules infers file type from the end of the path and rejects anything without an extension; SRS serves catalogue images from a CDN that has none, and those vendor urls are stored as-is. ABC images are downloaded and re-hosted, so ABC products were never affected.
- Hosts that serve extensionless assets can now be trusted by name, starting with SRS's CDN. That list is kept separate from the custom-dashboard embed allow-list, so trusting an image host does not widen where dashboards may be embedded.
- The deeper fix: urls already stored on a record are no longer re-validated. A full-document update sends stored values back untouched, so a check meant for newly supplied links was rejecting data the platform itself had written. Newly supplied links are still validated on both create and update.
- A url containing a stray percent sign (".../50%off.png") was also being rejected as malformed. It now falls back to the raw url and logs a warning instead.
- The same re-validation exposure exists in the other modules that received the url check (jobs, customers, assets, invoices, projects and others). The shared helper now supports the fix; applying it there is still pending.
