### API-4530 — SRS branch-availability gate for vendor-catalog creation

*Repo:* `master_service` · *Branch:* `API-4530` · *Ticket:* [API-4530 — SRS item availability search optimization](https://linear.app/zuperinc/issue/API-4530/srs-item-availability-search-optimization) · *Commits:* `c32a24d40`

- SRS vendor-catalog rows are now gated on the dedicated branch-availability API (`byItemCodes`) instead of pattern-matching the price API's free-text message, so a row is never created for an item a branch does not actually carry.
- Availability is fetched once per branch and applied uniformly across every catalog-creation flow and the product-details availability flag; the old "Item not Found" message is retained as a secondary check, and when availability can't be confirmed the item is skipped (fail-closed).
- Side effect of fail-closed gating: items the price API returns no row for are now skipped rather than created with a zero cost.

### API-4535 — submit supplier-catalog custom PO line items

*Repo:* `master_service` · *Branch:* `API-4535` · *Ticket:* [API-4535 — Update API logic for item variants and meta fields](https://linear.app/zuperinc/issue/API-4535/update-api-logic-for-item-variants-and-meta-fields) · *Commits:* `f840dcdae` `d87dd0ed1`

- Purchase-order line items added from an integrated supplier catalog (which carry no product or vendor-catalog link) were silently skipped when sending the PO to the supplier. They can now be submitted: the supplier identity the UI stamps on the line at add time is read directly, decoupling submission from the vendor catalog.
- A line stamped for one supplier is rejected if the PO's vendor belongs to a different supplier, and lines with incomplete supplier identity are skipped with a clear reason rather than failing the whole order. Live price refresh and branch "not found" checks now run for these lines too.
- Normal purchase orders and catalog-backed lines are unaffected; PO create/update validation was intentionally left untouched so partially-configured drafts can still be saved.
- Added supplier-identity filters to the vendor-catalog list API (`filter.supplier_product`, `filter.supplier_product_option`, optional `filter.uom`) so the UI can check whether a chosen supplier item already exists in a vendor's catalog — letting it pick a normal catalog line over a duplicate custom line.
