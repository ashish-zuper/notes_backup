### API-5048 — Supplier import product images to shared S3 folder
*Repo:* `master_service` · *Branch:* `API-5048` · *Ticket:* [API-5048 — Product Image optimization for template import](https://linear.app/zuperinc/issue/API-5048/product-image-optimization-for-template-import) · *Commits:* `0f5722005`

- Imported ABC Supply product images now upload to the shared `supplier_product_images/abc_supply/` S3 folder (same bucket + keypath as the scheduler-service import) instead of the company-scoped `supplier_products/<company_id>/` path, so both services share hosted objects per asset and the url cached on the shared supplier master product stays consistent across companies.
- Which providers get re-hosted (and where) is now driven by a per-provider folder map instead of a hardcoded provider check — enabling another provider is a one-line entry.
- Hardened tmp-file cleanup so the temporary image is removed even when the write itself fails, not only on upload success/failure.

### API-4851 — Resilient supplier catalog creation (retries + availability gating)
*Repo:* `master_service` · *Branch:* `API-4851` · *Ticket:* [API-4851 — Bulk connect is not working as expected](https://linear.app/zuperinc/issue/API-4851/bulk-connect-is-not-working-as-expected) · *Commits:* `cd2cc72f5`

- Supplier catalog creation no longer silently loses items when ABC/SRS pricing or availability calls fail transiently: the provider now reports which branches came back "undetermined" (a failed price request or a failed availability check), and each catalog flow automatically retries only those branches a bounded number of times instead of finishing as a false success.
- New-branch catalog creation is now safely re-runnable — it skips rows a previous run already wrote (so retries never duplicate), preserves distinct product-option rows that share a supplier item number, and reports accurate per-branch/per-job counts.
- Fixed a regression where a single partial availability-response chunk marked an entire SRS branch as out-of-stock in the live branch-availability lookup; the lookup now keeps the results it did get and only the catalog-creation path treats a partial failure as retry-worthy.
- Supplier branches with no email on file are created with a placeholder address instead of being dropped, and skip logs now record a clear reason (not-stocked vs no-price) so an item that priced successfully is never mislabelled "not found".
