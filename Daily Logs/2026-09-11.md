## Dev log

### API-5831 — QXO branch availability from brnAvail alone
*Repo:* `scheduler_service` · *Branch:* `API-5831` · *Ticket:* [API-5831 — QXO Product Availability Scope Update](https://linear.app/zuperinc/issue/API-5831/qxo-product-availability-scope-update) · *Commits:* `d57f7e4` `a4f15ec`

- QXO branch availability now comes from the branch-stocked flag alone; regional transferability no longer counts, on QXO's own guidance that the branch flag is the reliable signal for whether an item is stocked at the customer's assigned branch.
- Products that were only regionally transferable import as inactive from the next run, drop out of branch-scoped catalog search, and get their vendor catalog rows marked unavailable by the price sync. Nothing is soft-deleted — every run is a full recompute, so this reverses itself if the rule changes back.
- The import now aborts before writing anything if the dump yields no branch-stocked availability at all, logging the availability counters and a sample row. Previously an upstream rename or retype of that flag would have blanked availability across all 78k products with the run still reporting success.
- Hardened the guard after review: the abort only caught the flag disappearing, but a retype is the worse failure — non-boolean values like "N" read as truthy, which would have published the whole catalog as available at every branch. Non-boolean flags are now counted and abort the run too, so the flag's type no longer has to be checked by hand before a release.
- The logged branch count again covers every branch in the dump rather than only the stocked ones, and an aborted run now still emits its phase metrics line.
