### API-5140 — ABC PO submit: contacts + supplier-authored line identity
*Repo:* `master_service` · *Branch:* `API-5140` · *Ticket:* [API-5140 — ABC Submit PO updates as per Feedback](https://linear.app/zuperinc/issue/API-5140/abc-submit-po-updates-as-per-feedback) · *Commits:* `88c9fb566`

- ABC purchase orders now include the Order Submitter (`SM`) and Delivery Contact (`DC`) records the branch was missing, alongside the existing service-order-writer contact. Both use the person who sent the PO to the vendor — their name, email and phone — falling back to company details only when that user can't be resolved. Phone objects now carry the `ext` key ABC's schema requires; without it ABC rejected the order outright.
- Order lines now carry ABC's own item description instead of the Zuper/customer product name, which was causing fulfilment errors at the branch, and they order the family item's own item number rather than its parent — previously a Hickory variant was submitted (and priced) as its Black parent.
- A line whose supplier item code can't be established is now skipped with an activity entry instead of being ordered as the parent, so a wrong item can't ship silently.
- Dimensional items split into parent item number plus a length, with the webhook reconcile key rebuilt the same way the order response builds it, so price/quantity updates land on the right length.
- Line item remarks are passed through to the branch as a line comment.
- SRS order submission is untouched: supplier master products are only loaded for providers that consume them.
- Still open: sandbox submit to confirm ABC accepts a family item number and echoes it back, and no test coverage yet for the custom-line path.

### API-5204 — ABC delivery status derived from shipments

*Repo:* `master_service` · *Branch:* `API-5204` · *Commits:* `e5d648fc5` `59496d2f1`

- ABC purchase orders were taking their delivery progress from the order-level status, so a partially delivered order could report Delivered — permanently, since delivery only moves forward — and an order sitting at Invoiced showed no progress at all while its shipments were moving. Progress now comes from the shipments.
- Only ABC's four completion statuses can mark an order delivered, because ABC holds an order at Partial until the final delivery. A delivered shipment on an incomplete order caps at Arrived, which still allows the real completion later.
- Shipment status drives the state; the per-shipment event history is read only for its timestamp. ABC publishes the status vocabulary in full but only documents three event codes without calling them exhaustive, so only the closed vocabulary is mapped.
- Fixed three timestamp bugs found on review: the delivered date came from the first shipment rather than the last, could be taken from a cancelled shipment, and compared full timestamps against date-only values by category instead of chronologically.
- Statuses outside the mapped set are now skipped rather than recorded as unknown, and logged with the raw value so undocumented vocabulary from ABC is still visible. Documented no-meaning statuses stay silent to avoid logging on every pre-fulfilment webhook.
- Purchase order status promotion and the SRS integration are untouched.
- Still open: the persisted rows haven't been observed against a live database, and it's unconfirmed whether ABC populates shipments for pickup-flow orders — if it doesn't, those orders will show no progress until they complete.
