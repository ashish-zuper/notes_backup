## Dev log

### API-6257 — CPQ supplier branch choice
*Repo:* `master_service` · *Branch:* `api-6257-cpq-trigger-vendor-choice` · *Ticket:* [API-6257 — Supplier mapping feedback activity + vendor choice on CPQ trigger](https://linear.app/zuperinc/issue/API-6257/supplier-mapping-feedback-activity-vendor-choice-on-cpq-trigger) · *Commits:* `5a070a159` `3b7224e9d`

- The supplier branch chosen on the CPQ trigger is now stored on the quote by its vendor_uid (`cpq_status.cost_vendor_uid`) instead of an internal Mongo id, so quote APIs and webhooks no longer expose a primary key.
- Line-item costs and the quote's vendor now come from one branch lookup per proposal, so a quote can no longer be priced from one branch while showing another.
- If the chosen branch is no longer usable (inactive, removed, or its supplier disconnected), the proposal falls back to the default branch, adds a quote activity naming the branch used instead, and stops reusing the stale choice on recompute.
- A failed branch lookup now fails the proposal (the queue retries it) instead of silently costing at another branch.
- An empty `vendor_uid` on the CPQ trigger now means "no branch chosen" and uses the default (preferred supplier's favourite) branch, instead of returning a 400 and blocking the job status change.
