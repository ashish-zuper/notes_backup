## Dev log

### API-5736 — allow adding options to supplier-template products

*Repo:* `master_service` · *Branch:* `API-5736` · *Ticket:* [API-5736 — QXO - Cant add the options which were removed in the imported template](https://linear.app/zuperinc/issue/API-5736/qxo-cant-add-the-options-which-were-removed-in-the-imported-template) · *Commits:* `71f1890c9` `58a323aa6`

- Products imported from a supplier's order template could have their catalog managed, their provider unlinked and their options removed, but adding an option back and mapping it to a supplier item was rejected. Removed the provenance check that caused it, so the add path now behaves like the rest of that screen.
- The rule that a product maps to a single supplier item still holds — a re-added option can only point at the item the product was imported from, and a different item still conflicts. The check was also already missing from the bulk catalog-map API and the background fan-out that creates catalogs for the other branches, so the three write paths now agree.
- Also dropped the supplier lookup that only fed the removed check, saving a database round trip on every catalog-map create.
- Wrote up the impact analysis before changing anything, including two things left open: the same check was removed once in June and reverted three days later for a reason that was never recorded, and a template re-import can still silently repoint a manually added catalog row because it matches existing rows by branch and SKU without scoping to the product.
