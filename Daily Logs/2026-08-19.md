### master — catalog loader
*Repo:* `viz` · *Branch:* `master` · *Commits:* `cc8ff2c`

- Added `load_catalog` to `viz/loaders.py`, turning the source's one-row-per-variant catalog
  JSON into five normalized tables: `product` (grouped by key, first-seen wins on the
  invariant fields, mismatches logged as a `data_issue` instead of crashing), `variant`
  (one row per source row), `variant_uom` (exploding the pipe-delimited `skuUOM` list with a
  base-unit flag), `variant_attr` (sparse EAV, skipping empty values, JSON-encoding
  dict/list attribute values), and `variant_asset` (only when an asset is present).
- No cleaning at ingest: dirty/verbatim source values (HTML entities, a bogus `skuUOM="Yes"`)
  are stored as-is for a later task to flag.
- Verified against the fixture (203 products, 394 variants, 459 UOM rows, 2209 attr rows,
  122 asset rows) with `viz/tests/test_loaders_catalog.py` (10 tests, all passing), plus a
  re-check of Task 3's branch loader tests to confirm no regression.

### master — branch query layer
*Repo:* `viz` · *Branch:* `master` · *Commits:* `10d8fc7` `b77b8cd` `98a4443`

- Added `viz/queries.py`: the read-only query layer's shared foundation (whitelisted
  sort/filter dicts so no caller value ever reaches raw SQL, limit clamping, FTS5-safe
  free-text sanitization) plus branch listing, branch detail, branch-scoped product
  listing, and branch facet counts. Tasks 10 and 11 will build the product/variant
  query layer on top of these same helpers.
- Added `viz/tests/support.py` so every query/API test suite builds the fixture
  `catalog.db` once per process instead of re-running the full build pipeline per test.
- Fixed one flaky test assertion discovered against real fixture data: this fixture
  keeps the full 1,158-branch master list against a sparse SKU sample, so 648 branches
  are legitimately zero-stock and the dedicated empty-branch fixture (649) doesn't rank
  in the first 200 rows by name or branch number — pinned it with a free-text filter
  instead of relying on default pagination.
- Verified with `viz/tests/test_queries_branch.py` (17 tests) and the full suite
  (82 tests, all passing); branch 512's three-state availability partition confirmed
  as 3 stocked / 5 region-only / 8 total.
- Follow-up from review: the has_stock=True/False test only asserted
  non-emptiness on one side and a lone `assertIn` on the other, so a
  filter that ignored `has_stock` entirely would still have passed. Now
  asserts both sides are non-empty, internally consistent (all stocked /
  all unstocked), and sum to the full 1,158-branch count (510 with stock,
  648 without), keeping the branch-649 pin as a separate check.
- Second review pass found two more gaps. `tests/support.py` published the
  fixture DB path global before confirming the build succeeded, so one
  broken build would silently poison every later test module in the same
  process (masking the real error behind an unrelated "unable to open
  database file"); it now only publishes the path after a successful
  build, cleaning up and re-raising on failure. Separately, the free-text
  search path on `list_branch_products` (the only code that hits the FTS5
  index) had zero test coverage; added tests pinning real matches, a
  narrowing search, and six hostile inputs that must short-circuit rather
  than reach `MATCH`.

### master — dashboard stats query layer and HTTP API server
*Repo:* `viz` · *Branch:* `master` · *Commits:* `6bb2bc4` `394db69`

- Rounded out `viz/queries.py` with the remaining read-only lookups: UOM
  listing and drill-through, distinct branch dimensions (states/regions/
  markets) for filter UIs, category and brand facets, a data-quality issue
  browser, build metadata, and a dashboard stats summary (catalog totals,
  branch stock partition, availability-edge breakdown, coverage gaps, plus
  top-N series for categories/brands/UOMs/variants-per-product/issues).
- Added `viz/serve.py`: a stdlib-only, 127.0.0.1-bound JSON API and static
  file server on top of that query layer, using a thread-local sqlite
  connection per request thread (`ThreadingHTTPServer` hands each request
  its own thread, and sqlite3 connections aren't safe to share across
  threads). Maps `NotFound`/`BadParam` to 404/400 with a consistent error
  envelope, and serves `viz/web/` for everything else with path-traversal
  protection.
- Verified end to end against a freshly built fixture database: all 19 API
  endpoints (meta, stats, branch/product/variant listing and detail,
  branch-scoped products and facets, UOM/category/brand/issue browsers)
  returned 200.
- The "59 distinct branch states" figure turned out to be wrong: it counted
  the empty string as a state. There are 58 real states, and 11 branches carry
  no state at all. Corrected in the query expectations, the plan and the spec.

### master — branch dimension fixes, chart robustness and docs
*Repo:* `viz` · *Branch:* `master` · *Commits:* `c3c7c56` `4d28fc4` `32e46ba`

- Fixed the branch filter dropdowns. The region list grouped by (number, name),
  but `region_num 0` carries two different names in the source, so it produced

  regardless of value. The gutter is now clamped proportionally.

  ~30 seconds, and all thirteen expected row counts match the source exactly —
  including the 3,310,193 availability edges and their three-state split

- Added a README covering the build and serve commands, the data model, counter
  semantics, coverage caveats (45% of SKUs are stocked nowhere), and the two
  source quirks that bite any consumer of these dumps: `skuUOM` is a
  pipe-delimited list, and IDs must stay strings.
