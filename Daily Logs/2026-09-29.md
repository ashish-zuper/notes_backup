### API-6067 — Optional vendor email for supplier vendors
*Repo:* `master_service` · *Branch:* `API-6067` · *Ticket:* [API-6067 — Supplier / Vendor make vendor_email optional](https://linear.app/zuperinc/issue/API-6067/supplier-vendor-make-vendor-email-optional) · *Commits:* `d8af8f9b9`

- QXO branches come with no email, so imported supplier vendors were saved with a "-" placeholder and then failed the vendor edit with "Vendor Email should be valid".
- Vendor email is now optional only for supplier-imported vendors: branch import and re-sync save an empty email, and the vendor edit accepts and clears an empty email for them. Normal vendors still require a valid email.

- Existing supplier vendors still stored with "-" need a one-off Mongo data fix in each environment before QA.

### API-6084 — Scheduler OOM during the supplier import
*Repo:* `scheduler_service` · *Branch:* `API-6084` · *Ticket:* [API-6084 — Bug: Scheduler Service Restarts Due to OOM : us-west](https://linear.app/zuperinc/issue/API-6084/bug-scheduler-service-restarts-due-to-oom-us-west) · *Commits:* `1ce32a5` `c2f837d` `3f2057d` `c40ee4e` `827146c` `b2782fe`

- pm2 restarted the scheduler after it went over 1 GB during a full supplier import. The SRS branch availability sync and the ABC image syncs were started without waiting for them, so they ran alongside the next supplier's import in the same process. The restart left the job locked with no Slack alert.
- Each supplier's follow-up syncs now finish before the next supplier starts (SRS, then its branch sync, then ABC, then its image syncs, then QXO). The Slack "Completed" alert now means everything is done, and a full run takes longer.
- The SRS branch sync still runs 10 branches at a time, but now starts each one half a second after the previous, so SRS and Mongo get a steady flow of requests instead of bursts of 10.
- Each supplier's memory (RSS at start and at peak, heap, native memory) is now logged when it finishes, and the import's Completed log and Slack alert show the overall peak and which supplier hit it, so the headroom under pm2's 1 GB limit is visible on every run.
- Cut SRS memory: the full catalog is released before the branch sync, and the sync runs 5 branches at a time with a 1s pause and smaller reads. A local full run went from a 1,176 MB to a 791 MB peak with no slowdown.
- QXO no longer sends each product's raw record on every write when the product already exists, since the database ignores it; this trims the allocation churn behind QXO's write-phase memory.
- The import now runs SRS, then QXO, then ABC Supply, so ABC's image syncs, which have no time limit, no longer hold up QXO.
- Still open: refreshing the job lock between suppliers (Agenda re-runs a job that outlives its 17h lock), an idle timeout on SRS branch responses, ABC image syncs retrying failed images every round, capping Node's heap below pm2's limit, and the midnight price sync overlapping the import.
