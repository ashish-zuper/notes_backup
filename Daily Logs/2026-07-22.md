## Dev log

### API-5097 — Vendor Catalog API optimization

*Repo:* `master_service` · *Branch:* `API-5097` · *Ticket:* [API-5097 — Vendor Catalog API optimization](https://linear.app/zuperinc/issue/API-5097/vendor-catalog-api-optimization) · *Commits:* `5176fce7a`

- `GET /vendor_catalogs` no longer makes a live supplier-provider (ABC) availability call on every read. The live fetch and its DB write-back now run only when a caller explicitly passes `fetch_availability_from_provider=true`.
- Default reads serve the cached availability status, which a separate scheduler service already refreshes daily — cutting an external HTTP round trip and a Mongo write off the hot path, which was the main latency source on catalogs for large vendors/products.
- Response shape and the "check availability now" opt-in are unchanged.
