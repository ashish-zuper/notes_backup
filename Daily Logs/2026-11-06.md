## Dev log

### API-6825 — Custom object association definitions (PR 4 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-04-association-definitions` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `155505c44`

- Added settings APIs to list, create, update and archive associations between a custom object and a standard module or another custom object.
- Keys and default labels come from the two sides' names (e.g. `permit_property`); the relationship type, target and delete rule are fixed after creation, and cascade delete is only allowed between custom objects.
- Each side can choose whether its create form asks for the other side; a standard module's form can never require a custom object record, so existing create paths keep working.
- Opened API-6845 as a sub-issue for custom object records and links, and added the association requests to the Postman collection.

### API-6825 — Custom object role permissions (PR 5 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-05-permissions` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `a891d9b20`

- Added settings APIs to read and update each access role's rights on a custom object (view, create, edit, delete, and whether they reach all, team or own records).
- Roles that were never configured default to view-only on all records; a role that can create, edit or delete must also be able to view.
- Rights are stored now and will be enforced when custom object records arrive (API-6845).

### API-6825 — Custom object archive and restore (PR 6 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-06-archive` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `a68429595`

- Added settings APIs to archive and restore a custom object; archiving hides its fields, associations and records without deleting anything and frees a slot under the plan's object limit.
- Restoring counts against that limit, so archive-and-restore can't be used to exceed it; nothing blocks an archive yet since workflows and reports can't reference custom objects.
- Regrouped the Postman collection into one folder per area, with archive and restore last.

### API-6825 — Custom object follow-up fixes (PR 7 of 7)

### API-6845 — Custom object records (PR 1)

*Repo:* `master_service` · *Branch:* `api-6845-01-records` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `d27ebe139`

- Added record APIs for custom objects under `/objects/<object>`: create, list with cursor paging, search and sort, read, update and soft delete.
- Each record gets a readable ID from the object's prefix (e.g. `PRM-0042`); numbering, the archived check and an optional per-company record limit happen in one atomic step.
- Field values are checked with the same strict rules the versioned API applies to jobs (required fields, options, formats).
- Access follows the object's role permissions, including team and own-records scopes; records outside a user's scope return not found, and an archived object's records are read-only.
