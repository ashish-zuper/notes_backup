## Dev log

### API-5995 — Master product APIs show only branch-stocked variants
*Repo:* `master_service` · *Branch:* `API-5995` · *Ticket:* [API-5995 — Recomment API / Master Product APIs Behavioural Change](https://linear.app/zuperinc/issue/API-5995/recomment-api-master-product-apis-behavioural-change) · *Commits:* `fd5f20eae`

- Supplier master product list, detail and recommended APIs now always hide variants that none of the company's installed branches stocks, so users only see items they can actually order. Applies to ABC Supply and QXO, which have per-variant branch data.
- SRS is unchanged for now (product-level check only) until per-variant branch data is synced for it (API-6000).
- Recommendations skip a matched supplier product when none of its variants is stocked at an installed branch, instead of returning it with no variants.
- Detail API's `available_only` keeps its stricter meaning: also hides price rows the pricing branch doesn't stock or the supplier didn't quote.

### API-6000 — Store SRS variant-level branch availability
*Repo:* `scheduler_service` · *Branch:* `API-6000` · *Ticket:* [API-6000 — SRS: store variant-level branch availability](https://linear.app/zuperinc/issue/API-6000/srs-store-variant-level-branch-availability) · *Commits:* `35f8e75`

- Nightly SRS branch sync now records which variants each branch stocks, not just which products, matching variants by product id plus SRS's `productOptionsId`. Only changed variants are written, and products no longer listed at a branch lose it from all their variants.
- Nightly SRS import stores `product_options_id` on each variant and keeps existing variant branch lists instead of wiping them on every rewrite.
- A variant that hasn't been synced is now stored with no branch list rather than an empty one, so it can't be mistaken for "stocked nowhere".
- Per-branch sync log now reports variants matched, added and removed, and branch variants with no match.

### API-6000 — Carry SRS variant key through master products
*Repo:* `master_service` · *Branch:* `API-6000` · *Ticket:* [API-6000 — SRS: store variant-level branch availability](https://linear.app/zuperinc/issue/API-6000/srs-store-variant-level-branch-availability) · *Commits:* `955ae325c`

- Master product schema and the import worker now keep SRS `product_options_id` on variants, so worker rewrites don't drop the key the branch sync depends on.
- The key is internal and is kept out of the master product detail and recommendation responses.
- SRS still uses product-level availability; switching it to the per-variant data is a follow-up once the synced data has been verified.
