## Dev log

### API-4477 — SRS bug bash

*Repo:* `master_service` · *Branch:* `API-4477` · *Ticket:* [API-4477 — SRS - bug bash - 9/6](https://linear.app/zuperinc/issue/API-4477/srs-bug-bash-96) · *Commits:* `4f5eaddd2` `982b2ccab` `e19af0612`

- Imported supplier products are now validated on creation instead of being saved unvalidated. The required fields are all guaranteed before the save (generated/derived or already checked by the import job), so this brings the import in line with the normal product-create path without changing what gets imported.
- Changing a vendor catalog's unit of measure on one branch now applies that UOM to the same product across every other branch of the supplier provider, instead of only the edited branch. The edited branch updates immediately; a background job then re-prices the product at the new UOM for each other branch and updates UOM and cost together (for all options of the product). Branches where the supplier has no price for the new UOM are left as-is so UOM and price stay consistent. Also fixed the background job reading the wrong supplier-product fields, which had left the other branches unpriced.
- Fixed imported supplier products creating their option values as unavailable — every variant of a freshly imported product was flagged unavailable. Options are now created as available, matching the schema default and the manual product-create path.

### disable-supplier-integration-env-gate — drop dev-only kill-switch

*Repo:* `master_service` · *Branch:* `feature/disable-supplier-integration-env-gate` · *Commits:* `1f9cca9e6`

- Supplier integration is no longer restricted to development data centres. The environment kill-switch (which only let the feature run where the DC was named "development") has been removed entirely, across the full submit → tracker → webhook → worker round-trip, so the integration behaves the same in every environment.
- Whether a company's purchase orders hand off to the supplier is now governed solely by the existing per-tenant supplier-integration setting, rather than that setting plus an environment check. SRS-specific shape validations (shipping zip, due date, delivery method) now apply whenever the vendor is an integrated SRS vendor, regardless of environment.
