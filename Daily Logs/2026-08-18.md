## Dev log

### API-5482 — QXO supplier authentication

*Repo:* `master_service` · *Branch:* `API-5482` · *Ticket:* [API-5482 — Auth Setup - QXO](https://linear.app/zuperinc/issue/API-5482/auth-setup-qxo) · *Commits:* `715fa5d94`

- A QXO supplier provider can now be connected and stay authenticated. The split matches ABC Supply: the platform app owns the OAuth consent leg and writes the credentials into the provider record, and this service runs the refresh grant from then on. Creating a QXO provider now requires a refresh token.
- QXO's identity provider is Keycloak, and the refresh grant takes the client id only — no client secret — so the requested scopes are a single named constant rather than scattered literals.
- Access tokens are cached until shortly before they expire, and concurrent callers share one in-flight refresh. That matters because the refresh token rotates on every use: without the sharing, parallel requests would spend it more than once and invalidate each other.
- Rotated refresh tokens are written back. If a response comes back without a replacement, the stored token is kept rather than blanked, so a partial response can't strip a tenant's only way to recover.
- Transient failures no longer cost a tenant their connection. A timeout or a 5xx from the identity provider leaves the credentials intact; only a definitive authentication failure marks the connection as needing reconnection. ABC treats a timeout as fatal here, which permanently destroys its refresh token — deliberately not copied.
- QXO access tokens are tied to a login session and can be revoked well before they expire, so an expired-token response (401, plus the 417 and 419 codes QXO uses for the same thing) now triggers one re-mint and a single replay instead of failing the request outright.

Two things still need QXO to confirm: whether the realm reads the plural `scopes` parameter the working request sends (if not, tokens carry the client's defaults, and order submission scopes were missing from the sample token), and the app-store slug used to notify the platform when a connection drops.
