## Dev log

### hotfix/srs-item-not-found-option-key-mismatch — SRS "Item not Found" catalog skip

*Repo:* `master_service` · *Branch:* `hotfix/srs-item-not-found-option-key-mismatch` · *Commits:* `f148ee53e`

- Fixed a bug where mapping an SRS product to a vendor catalog still created a
  catalog row even when the SRS price API reported "Item not Found" — the
  guard that should skip those items silently failed.
- Root cause: for supplier options whose value equals the product name, the
  price lookup collapses the option to "N/A" before calling SRS but rebuilt the
  result key from the raw option value, so the price entry (carrying the
  not-found message) was never matched. The skip check then saw nothing and let
  the row through with a 0 cost and a blank supplier message.
- Aligned the lookup key with how the price query is actually keyed in both
  catalog-creation paths (the per-vendor create and the multi-branch fan-out).
- Reviewed adjacent flows; noted but did not change two related gaps: a global
  UOM dedup that can break multi-product payloads, and the `/catalog_map/bulk`
  path which lacks the not-found skip entirely.
