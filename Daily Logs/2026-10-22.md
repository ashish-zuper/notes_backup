### API-6389 — OAuth sign-in behind a path-stripping proxy
*Repo:* `master_service` · *Branch:* `API-6389-review-fixes` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `fc50a6d9a`

- Dev environments sit behind a proxy that strips a path prefix such as `/api/v8`, so the OAuth login and consent pages were sending the browser to `/oauth/...` on the shared dev host, which can't tell which dev environment is meant.
- A new optional `OAUTH.path_prefix` setting adds the stripped prefix back to every URL sent to the browser (login and consent pages, form targets, Send OTP) and to the OAuth library's own redirect and sign-in cookie paths; unset in staging regions and production, where nothing changes.
- The prefix is validated at startup so it can only be plain path segments, never something that would redirect to another host; a test drives the real OAuth library through a stripped path.

### API-6389 — Staging front door routed to a dev environment
*Repo:* `zuper_account_service` · *Branch:* `api-6389-oauth-front-door` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `03ef4f0`

- A new optional `OAUTH.api_url_override` setting (staging only) sends all OAuth traffic from the account service — the company-step redirect, token, revoke and the public key fetch — to one API such as `https://development.zuperpro.com/api/v8` instead of the company's region, so OAuth can be tested end to end against a dev environment.
- Front-door logs now record the URL each request was actually sent to, and region prefixes that clash with JavaScript built-ins are treated as unknown regions (400) instead of failing with a 503.
