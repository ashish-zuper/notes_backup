### API-6389 — OAuth scopes defined in code, consent grouped by module
*Repo:* `master_service` · *Branch:* `API-6389-scope-constants` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `3234df291` `61f8468c7` `fdd78ebbb`
- OAuth scopes and the trusted AI apps (Claude, ChatGPT, Grok, VS Code, Cursor) now live in code instead of per-region YAML, so every region gets the same list and changes go through review and tests.
- Delete scopes are defined but not offered yet; a write scope also covers reading the same module.
- The consent screen shows one access choice per module (view only, view/create/update, or no access) instead of a checkbox per scope, so it stays short as more modules are opened.
- The connections API returns a per-module access summary and the scope list API returns module details, so the settings page doesn't have to parse scope names.
- OAuth logs now name the user, company, app and connection for both refused and accepted requests.
- Plan updated: the generic notes route is planned for OAuth, and there will be no separate admin scope level (admin-only routes stay closed to connected apps).
- Scopes now cover every module of the product, named and grouped the way the web app shows them: 25 modules, including Jobs (with the schedule), Tasks, Appointments, Material orders, Supplier integrations, Financing and Workflows. Organizations share the customer scopes.
- 682 API routes are open to connected apps for reading or writing. Admin-only and delete routes stay closed, as do routes that move money, change user roles, run credit checks, place paid orders or expose provider credentials.
- Notes, attachments, folders, comments and expenses take the scope of the record the request names, so a file on an invoice is exactly as protected as the invoice. Email templates can be read with the settings scope.
- The consent screen's module list scrolls on its own, so Allow and Deny stay in view however many modules an app asks for.
- Opened as PR #2742, stacked on the ChatGPT sign-in PR #2710.
