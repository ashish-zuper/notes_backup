### API-6389 — OAuth 2.1 provider bootstrap
*Repo:* `master_service` · *Branch:* `API-6389` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `6e2e547b9`
- Added the OAuth 2.1 authorization server foundation inside master_service using `oidc-provider` 9.12.2, switched off unless `OAUTH.enabled` is set, so existing logins and API keys are untouched.
- Each region signs its own ES256 tokens, prefixes codes and refresh tokens with its region name for routing, and requires PKCE for every app; Claude, ChatGPT and VS Code identify themselves through metadata documents from allowlisted hosts, Cursor through a pre-registered client.
- A bad OAuth config or old Node version now logs and leaves OAuth off instead of crashing the server; verified locally with 25 unit tests and 7 API checks.
- Before coding, prototyped the library and captured how Claude Code, VS Code and Cursor really connect, which fixed the client registration design and the redirect URIs used.
