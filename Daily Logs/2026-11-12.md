## Dev log

### API-6845 — Custom object record updates
*Repo:* `master_service` · *Branch:* `api-6845-03-extras` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `25f695b63`

- Two people updating different fields of the same record at the same time no longer lose one update; a record update now writes only the fields it sends instead of the whole field list.
- New fields on an update keep their filter copy in step with the value, and fields saved without a group are matched however the empty group was stored.
- A typical record update now takes three database round trips instead of about nine.

### API-6845 — Custom object access, numbering and bulk actions
*Repo:* `master_service` · *Branch:* `api-6845-04-access-and-bulk` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `c225377dc`

- Users without saved custom object rights now get their base role's rights: admins everything; team leaders and field executives create, and view and edit their team's or their own records; only admins delete unless an access role allows it.
- An object a user can't see is treated as not found on every route (settings, records, bulk, notes, links), and is left out of object lists and association targets; managers still see every object in settings.
- Record numbers now come from the shared counters collection like other modules, and custom objects can have their next number set from the module counter settings (forward only).
- Custom object names can no longer match a standard module's name; object details now include field and association counts.
- Fields restricted from a user are marked hidden on record reads and link previews, as in other modules; the primary display field can't be hidden.
- Bulk field update and bulk delete for records, queued to a worker that applies the normal single-record rules; deletes refused by delete rules are noted on the record's activity.
- Shared lookups, record filters, result handling and field restrictions were consolidated so each rule is implemented once.

### API-6845 — Custom object record filters and counts
*Repo:* `master_service` · *Branch:* `api-6845-05-list` · *Ticket:* [API-6845 — Custom Objects: records and links](https://linear.app/zuperinc/issue/API-6845/custom-objects-records-and-links) · *Commits:* `92d7ee4a6`

- Custom object records can now be filtered and counted: a filter API, count APIs for the list and for filters, and keyword search over the record ID, the primary field and the secondary fields the user can see.
- Each record keeps a typed copy of its filterable values, so number and date ranges compare correctly and multi-rule filters use an index; locally, filtered counts ran 2.5–9× faster than the approach other modules use for custom field filters.
- Date filters cover whole days in the user's timezone, as in other modules; hidden fields can't be filtered on, and a field's type can't change once records hold values for it.
- Record lists default to cursor pages (offset pages when a page number is sent) and include the total unless turned off.
