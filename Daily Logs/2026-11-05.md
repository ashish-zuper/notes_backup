## Dev log

### API-6825 — Custom objects storage (PR 1 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-01-schemas` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `81fa2a30e`

- Added storage for company-defined custom objects: a definition collection keyed by one immutable module name (`CO_PERMIT`), so the existing custom field engine works for them unchanged.
- Added association definitions between any two modules, including many-to-one, with per-side labels and create-form picker settings; keys, sides and cardinality are locked once saved.
- Added a per-role permissions table and a "Manage Custom Objects" settings permission; the feature is off per company until its policy enables it, with default limits of 3 objects, 100 fields and 25 associations.
- Mongo indexes are listed as comments (created directly on the cluster), and the object keeps a live record count for the settings list.

### API-6825 — Custom object settings APIs (PR 2 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-02-object-crud` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `a3cd77316`

- Added settings APIs to list, view, create and update custom objects; creating one also sets up its "General" field group and required primary field, and undoes partial writes if a step fails.
- Gated every call on the company's custom objects policy, with writes limited to admins or roles holding "Manage Custom Objects"; plan limits and reused API keys are refused.
- Custom field definitions now accept custom object modules, while the existing custom field routes refuse them until they get the full custom object checks.
- Regrouped the module's constants and standardised its log messages.

### API-6825 — Custom object fields (PR 3 of 6)

*Repo:* `master_service` · *Branch:* `api-6825-03-fields` · *Ticket:* [API-6825 — Custom Objects Implementation](https://linear.app/zuperinc/issue/API-6825/custom-objects-implementation) · *Commits:* `f05bd095f`

- Opened the existing custom field and field group settings APIs to custom objects, behind the feature switch, the "Manage Custom Objects" permission and a check that the object exists; standard modules behave as before.
- Added custom object field rules: a per-object field limit, a primary display field that stays a required single-line field and can't be deleted (nor its group), and secondary fields cleared when their field is deleted.
- Layouts can now be created for custom objects; the bulk custom field create API stays closed to them.
- Created a Postman collection for the custom object settings APIs.
