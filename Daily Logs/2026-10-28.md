### API-6389 — ChatGPT sign-in with private_key_jwt
*Repo:* `master_service` · *Branch:* `API-6389-chatgpt-private-key-jwt` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `cb5e6c0ba`
*Repo:* `zuper_account_service` · *Branch:* `api-6389-front-door-private-key-jwt` · *Ticket:* [API-6389 — OAuth 2.1 v1: regional authorization server + stateless front door](https://linear.app/zuperinc/issue/API-6389/oauth-21-v1-regional-authorization-server-stateless-front-door) · *Commits:* `840125e`

- ChatGPT couldn't connect: its client metadata document requires signed client assertions (private_key_jwt), which regions rejected at sign-in.
- Regions now accept private_key_jwt, and accept assertions addressed to the front door's token and revocation URLs; a captured ChatGPT request showed it signs for the front door's token URL.
- Client authentication methods now come from one constant in master_service instead of separate lists; company apps stay limited to secret-based methods.
- The front door now advertises private_key_jwt and its signing algorithms, since ChatGPT only signs when the server advertises the method.
- Example config gained a ChatGPT scope entry; without one, ChatGPT connects but every API call is refused.
- Opened as stacked PRs: master_service #2710 on #2625, zuper_account_service #10 on #9.
