Bug Report: Logical Flaw in continueEventMessageProcess()

  File: /lib/event_message_ack_handler.js
  Function: continueEventMessageProcess() (lines 281-316)
  Severity: Medium
  Type: Logic Error - State Management Flaw

  ---
  Summary

  The continueEventMessageProcess() function incorrectly clears the current_running_execution_company_ids tracking array when is_all_same_company = false, causing premature loss of state about which companies are currently being processed.

  ---
  Current Problematic Code

  ---
  Problem Description

  When is_all_same_company = false, the function clears current_running_execution_company_ids without verifying that those companies have actually completed their executions.

  Reproduction Scenario

  Step 1: Initial State
  - current_running_execution_company_ids = [100, 200] (actively processing)
  - Companies 100 and 200 have executions IN_PROGRESS

  Step 2: New Company Queues Execution
  - Company 300 creates a new queued execution
  - queued_execution_company_ids = [100, 200, 300]

  Step 3: Function Evaluation
  is_all_same_company = [100, 200, 300].every(id => [100, 200].includes(id))
  // Returns: false (because 300 is NOT in current_running list)

  Step 4: Buggy Behavior
  // Since is_all_same_company = false:
  current_running_execution_company_ids = [];  // ← Clears [100, 200]
  return true;

  Result: State tracking is lost even though companies 100 and 200 still have active executions.

  ---
  Impact

  1. State Loss: Tracking information about currently processing companies is discarded prematurely
  2. Ineffective Throttling: The tracking mechanism designed to prevent redundant polling doesn't work correctly
  3. Potential Race Conditions: Loss of state could lead to multiple polling attempts for the same company
  4. Inconsistent Behavior: Company-level limits in getExecutions() should prevent violations, but the tracking becomes unreliable

  ---
  Root Cause

  The logic assumes that if is_all_same_company = false, it means new companies are available, so it's safe to clear the tracking list and allow polling. However, this doesn't account for the fact that previously tracked companies may still have active executions.
