### API-7140 — normalized supplier brands
*Repo:* `master_service` · *Branch:* `api-7140-normalized-brands` · *Ticket:* [API-7140 — Supplier TakeOff: Normalized supplier brands](https://linear.app/zuperinc/issue/API-7140/supplier-takeoff-normalized-supplier-brands) · *Commits:* `726487945` `dd2c36cf5`

- Added one brand list shared by SRS, ABC Supply and QXO, with the supplier spellings that resolve to each brand, so self-serve can filter supplier products by brand across suppliers.
- Seeded every brand from prod (3,703 rows), but only the 12 brands of the GBB catalog are active and shown to companies; the rest stay inactive until reviewed.
- Fixed brand folding so "Berger Building Products" and "Berger" are one brand; 29 brands joined their plain name this way.
- Merged only spellings checked by hand (CertainTeed EverNew/Gypsum/Insulation, Owens Corning Sales, Atlas Roofing-Comm, four ABC vendor names); automatic prefix matches wrongly join unrelated companies.
- Placeholder brands such as "Manufacturer Varies" and generic words such as "Metal" resolve to an inactive `other` brand.
- The create-or-update seed logic is now shared by the category and brand seeds.
- Brand seed and list logs now go through the supplier module's logging helpers and documented events, which its OpenSearch searches and alerts rely on.

### API-7196 — custom objects review follow-ups
*Repo:* `master_service` · *Branch:* `api-7196-custom-objects-review-follow-ups` · *Ticket:* [API-7196 — Custom Objects: review follow-ups](https://linear.app/zuperinc/issue/API-7196/custom-objects-review-follow-ups) · *Commits:* `405654ecc` `6a43b9ba7` `d12b79397` `400f9ac7f` `26d51833f` `a84c231a2` `430104255` `a504b591b`

- Custom object record lists, filters and link panels now return at most 100 rows per page (was 1000), to keep each page light; a larger `count` is refused with a message naming the limit.
- The role permissions API the apps load at startup now also lists a custom role's rights on each active custom object, as permission rows keyed like other modules' (`co_permit.view`, `.new`, `.update`, `.delete`), so the apps can show object icons and actions with their usual permission checks.
- Those rows carry fixed, non-null uids and a module order, because the Android apps fail to read the permission list when those fields are null.
- A user with a custom role now gets only the rights saved for that role on each object; without saved rights the object is hidden. Users without a custom role keep their base role's rights, so only admins delete.
- The custom object links API now names standard modules by the path their own APIs already use (`jobs`, `assets`, `property`), so custom objects don't introduce new path names; the old singular names (`job`) are refused.
- The record ID column and filter on custom object lists are now labelled "ID" in every language.
- Linked records in custom object link panels now say whether they are active or deleted, and a job, customer or other standard record deleted in its own module stays in the panel marked deleted, the way job details still shows a deleted customer.
- Filtering custom object records by a linked record is now a normal filter rule, the same way jobs filter by customer: each association shows up in the filter panel as a lookup (e.g. "Jobs" searching the jobs list), can take several records, combines with other rules, and works in saved views and bulk actions. The details-page card keeps its simple query parameters, which build the same rule.
- Owner changes and links on custom object records now show in the activity feed the way field changes do, with the old and new owner or the linked record in the activity details, instead of a plain sentence.
- Custom object record details now include the record's attachments and counts of its notes, attachments, activity and links, like job details does; they are worked out on each read and skipped when `fields_to_select` leaves them out. The attachment list's formatting moved into a shared helper so both APIs return attachments the same way.
- Fixes from a review of these changes: the owner-change activity now names the new owner, details only compute attachments and counts when `fields_to_select` asks for them at the top level, and a linked-record filter takes at most 100 records.

### API-7141 — normalize category and brand on supplier products
*Repo:* `master_service` · *Branch:* `api-7141-normalizer` · *Ticket:* [API-7141 — Supplier TakeOff: Normalize category and brand on supplier master products](https://linear.app/zuperinc/issue/API-7141) · *Commits:* `8e566ac29` `2f9b00161`

- Added the normalizer that fills each supplier product's normalized department, type and brand from the category mappings and the brand list; on the prod dump it reproduces the analysis behind the seed files for all 132,371 products.
- ABC brands come from the product name first and the vendor second; SRS and QXO use their brand field and read the name only when it is a placeholder.
- A background job runs it over every live product, one run at a time, writing only changed products; supplier values and brand spellings it has not seen become new unreviewed mappings and inactive brands, and product counts are refreshed.
- Admins can preview the result for up to 100 products, queue a run (with a dry-run option) and read its summary.
- Added unit tests for the normalizer rules, since they run nightly and will keep changing.
- Normalization logs now go through the supplier module's logging helpers, with a documented event for a queued run.
